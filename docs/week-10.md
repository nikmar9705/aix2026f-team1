## 막힌 지점 / What is blocked

1. **음료가 메뉴로 계산됨 (#4 음식 프로필 필터)** — 콜라·맥주 같은 음료가 메뉴(dish)로 저장되어 있다. 콜라에는 금지 재료가 없어서 "안전"으로 판정되고, 식당은 안전 메뉴가 하나만 있어도 "맞는 식당"이 된다(`restaurantFits`). 그래서 비건이나 할랄을 켜도 치킨집이 맞는 식당으로 나오고, 같은 이유로 "vegan-option" 배지도 붙는다(`badgesFor`).
2. **지도 핀이 식단 기준으로 흐려지지 않음 (#4)** — 핀은 알레르기 기준(`fadedForAllergies`)으로만 흐려진다. #4 완료 조건("할랄·비건·돼지고기 제외를 선택하면 맞지 않는 핀은 흐리게 표시")을 아직 충족하지 못했다.
3. **신뢰 배지(#8)가 시작되지 않음** — DB에는 `verified_count`, `last_checked` 칸이 있지만, 화면에는 신뢰도·검증 횟수·"미검증" 표시가 아직 없다.

## 디버깅 요청 4요소 / Four parts of a debugging request

(1번 막힌 지점 기준)

- 증상 Symptom: 비건 프로필에서 치킨집 "더치킨"(r05)이 홈 추천 목록에 나오고 "vegan-option" 배지가 붙는다.
- 재현 Steps: ① 프로필 탭에서 비건을 켠다 ② 홈 탭을 연다(더치킨이 거리 설정 안에 있는 상태) ③ 목록에서 더치킨을 찾는다
- 기대 Expected: 비건이 먹을 수 있는 음식이 없으므로 목록에서 빠지고 배지도 없어야 한다.
- 실제 Actual: 콜라(재료 태그 없음)가 "안전"으로 계산되어 더치킨이 맞는 식당으로 표시되고 배지가 붙는다. 할랄 프로필에서도 같은 이유로 맞는 식당이 된다.

## 데모 시나리오 초안 / Draft demo scenario

할랄을 지키고 땅콩 알레르기가 있는 ERICA 외국인 유학생이 학교 근처에서 먹을 곳을 찾는다.

1. 앱을 열면 ERICA 중심 지도에 식당 핀이 보인다 (#1)
2. 프로필 탭에서 할랄과 땅콩 알레르기를 켠다. 앱을 다시 열어도 저장되어 있다 (#4, #14)
3. 홈 탭에 거리 설정 안의 맞는 식당이 추천 순위대로 나온다 (#6, #7)
4. 식당을 누르면 메뉴가 안전 / 먼저 확인 / 피하기로 나뉘고, 땅콩이 든 메뉴는 숨겨지며 "보기"로 다시 볼 수 있다 (#5, #14)
5. 메뉴를 누르면 직원에게 보여 줄 한국어 주문 카드가 전체 화면으로 뜬다 (#9)
6. "예약하기"를 누르면 전화번호와 전화·복사 버튼, 한국어 문장이 나온다 (#16)

## 검증하지 않은 것 / Not verified  → `ETHICS.md` 4절

| 무엇을 검증하지 않았나 | 왜 | 남는 위험 |
|---|---|---|
| 시드 메뉴의 재료 태그(contains / may contain) | 메뉴판·공개 자료를 보고 입력했고, 아직 식당 직원에게 직접 확인하지 않았다. 시드 SQL의 모든 메뉴가 `verified_count = 0`, `last_checked = null`이다 | 태그가 틀리면 할랄이 아닌 음식이나 알레르기 유발 음식이 "안전"으로 표시될 수 있다 |
| 화면의 "미검증" 표시 | #8(신뢰 배지)이 아직 구현되지 않았다 | 사용자는 "안전"이 확인된 정보인지 추정인지 구분할 수 없다 |
